Отчёт по лабораторной работе №1

Цель работы

Освоить обмен данными через UDP и TCP, клиент-серверную архитектуру, многопоточную обработку подключений и базовую структуру HTTP-запросов и ответов.

Задание №1 — UDP-приветствие

udp_client.py отправляет датаграмму Hello, server на UDP-сервер. udp_server.py выводит полученный текст, отвечает Hello, client и завершает работу. Установление соединения не требуется, поскольку UDP работает с отдельными датаграммами.

Задание №2 — TCP-математическая операция

Выполнен вариант №2: площадь треугольника по основанию и высоте.

Клиент запрашивает два числа и передаёт их серверу одной строкой. Сервер проверяет данные и вычисляет результат по формуле:

S = a × h / 2

Основание и высота должны быть положительными. TCP обеспечивает надёжную доставку запроса и ответа.

Задание №3 — HTTP-ответ из файла

HTTP-сервер реализован непосредственно на TCP-сокете. Для GET-запроса он читает разметку из отдельного файла index.html, добавляет сохранённые данные и формирует HTTP/1.1-ответ со статусом, Content-Type и корректным Content-Length в байтах.

Задание №4 — многопользовательский чат

chat_server.py принимает TCP-подключения и создаёт отдельный threading.Thread для каждого клиента. Подключённые пользователи хранятся в общем словаре, доступ к которому защищён threading.Lock. Сообщение одного участника рассылается всем остальным. Сервер проверяет пустые и повторяющиеся имена, а команда /quit завершает клиентскую сессию.

Задание №5 — веб-сервер оценок

Тот же HTTP-сервер обрабатывает два метода:

  • GET загружает index.html и возвращает форму со всеми сохранёнными оценками;
  • POST разбирает тело application/x-www-form-urlencoded, проверяет поля subject и grade, сохраняет запись и возвращает обновлённую страницу.

Данные находятся в экземпляре GradeBook и существуют только до остановки процесса, как требуется для хранения в памяти.

Структура HTTP-обмена

Сервер читает заголовки до разделителя \r\n\r\n, получает длину тела из Content-Length и дочитывает POST-тело полностью. Поддерживаются статусы:

  • 200 OK для корректных GET и POST;
  • 400 Bad Request для неполных или пустых данных;
  • 404 Not Found для неизвестного пути;
  • 405 Method Not Allowed для неподдерживаемого метода;
  • 500 Internal Server Error, если файл index.html недоступен.

Тестирование

Автоматические тесты проверяют:

  • реальный UDP-обмен обязательными приветствиями через localhost;
  • формулу площади, проверку параметров и реальный TCP-обмен;
  • передачу сообщений между клиентами многопользовательского чата;
  • ограничения строчного TCP-протокола;
  • загрузку index.html, обработку GET и POST, хранение оценок;
  • HTTP-статусы, Content-Length и полное чтение POST-тела.

Команды запуска программ и проверок приведены в README.

Ограничения

Все программы являются учебными. Шифрование и аутентификация отсутствуют. Оценки не сохраняются после перезапуска HTTP-сервера. Для подключения с другого устройства может потребоваться изменить --host и разрешить порт в брандмауэре.
