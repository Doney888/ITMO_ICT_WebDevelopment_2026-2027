Интерфейсы и обработка запросов

Роли

Гость читает каталог, карточки и отзывы. После регистрации пользователь может добавлять выступления, управлять своими регистрациями и писать отзывы. Пользователь с is_staff видит таблицу участников, формы результатов и учебные страницы практик. Права Django-admin дополнительно регулируются стандартными разрешениями Django; суперпользователь имеет полный доступ.

Проверки выполняются дважды по назначению: шаблон показывает доступные действия, а сервер проверяет право выполнить запрос. Ручной ввод URL или изменение POST не позволяют получить права только потому, что кнопка отсутствовала на странице.

GET на адресе удаления показывает подтверждение, но не изменяет БД. Для выхода GET явно запрещён и возвращает 405.

Каталог

conference_list начинает с QuerySet всех конференций. Если q непустой, применяется поиск icontains по названию, описанию и месту через Q с логическим ИЛИ. Затем накладывается выбранная тематика. Поэтому поиск и фильтр работают совместно.

Пример запроса:

/?q=Сети&topic=1&page=2

Paginator разбивает отсортированную выборку по шесть записей. Тематики загружаются через prefetch_related, чтобы не выполнять отдельный запрос для каждой карточки. Параметр page исключается из копии QueryDict перед построением ссылок; остальные параметры сохраняются при переходе между страницами.

Идентификаторы topic и conference проверяются filter_id: допускаются только ASCII-цифры, положительное число и диапазон signed bigint. Невалидный параметр игнорируется, в том числе строка из 5000 цифр. Корректный, но отсутствующий идентификатор даёт пустую выборку.

Создание выступления

  1. login_required проверяет сессию; гостю предлагается войти.
  2. Представление ищет конференцию и проверяет существующую регистрацию.
  3. RegistrationForm проверяет тему и аннотацию.
  4. save(commit=False) создаёт объект в памяти, не записывая его сразу.
  5. Сервер назначает conference и author из URL и request.user.
  6. Запись сохраняется внутри transaction.atomic; уникальность пары защищена БД.
  7. После успеха отправляется redirect на карточку конференции.

Проверка существующей записи улучшает сообщение для пользователя. Уникальное ограничение всё равно необходимо: между предварительной проверкой и сохранением может прийти второй запрос.

При недопустимой форме сервер возвращает ту же страницу с введёнными данными и ошибками. После успешной записи используется переход POST → redirect → GET, чтобы обычное обновление страницы не повторяло отправку формы.

Редактирование и удаление

get_object_or_404 для редактирования и удаления ищет регистрацию одновременно по pk и author=request.user. Чужая и отсутствующая запись возвращают 404. Присланные поля другого автора, конференции или результата не входят в форму и не используются для изменения этих свойств.

При удалении GET выводит confirm_delete.html. Только POST вызывает delete и возвращает пользователя к конференции. Передать чужой pk недостаточно: проверка владельца выполняется до обработки действия.

Результаты и таблица участников

participants проверяет is_staff и выбирает регистрации с select_related для конференции и автора. Можно выбрать одну конференцию или показать все. В таблице нет паспортов, адресов и других данных практического модуля.

result_edit также проверяет is_staff на сервере. Его ModelForm принимает только result с допустимыми значениями. Django-admin предоставляет второй предусмотренный условием способ выставления того же результата.

Формы, CSRF и шаблоны

Пользовательские шаблоны Jinja2 наследуют base.html. Окружение добавляет функции url, static и get_messages. request и csrf_input предоставляет Django-бэкенд Jinja2 при рендеринге с объектом запроса.

Формы POST включают csrf_input. CsrfViewMiddleware сверяет токен с cookie; неверный или отсутствующий токен отклоняется до изменения данных. Сессии и хеширование паролей используют штатные средства Django.

Автоэкранирование включено Django-бэкендом Jinja2. Пользовательские названия, тексты и отзывы не помечаются safe. В форме фильтр safe используется только для статических подсказок Django, содержащих HTML-разметку.

Коды ответов

Ответ Пример
200 Страница, пустая выборка, форма с ошибками, подтверждение удаления
302 Успешное сохранение, вход/выход, переход гостя на вход
403 Обычный пользователь обращается к привилегированной странице; неверный CSRF
404 Неизвестная конференция или недоступная чужая регистрация
405 GET на маршрут выхода
